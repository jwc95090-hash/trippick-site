# TRIPPICK 고객 사이트 UX 실행 기준

이 문서는 고객 사이트의 기획·디자인·구현을 하나의 기준으로 유지하기 위한 실행 문서입니다.

## 제품 정의

TRIPPICK은 캠핑 경험이 적은 사용자가 지역·인원·숙박 유형·필수 시설을 기준으로 캠핑장을 찾고, 최대 3곳을 같은 기준으로 비교한 뒤 예약 전 확인과 준비까지 이어가도록 돕는 서비스입니다.

## 핵심 흐름

발견 → 조건 검색 → 결과 탐색 → 비교 → 상세 확인 → 문의/예약 → 결제 → 준비 → 후기

## 14단계 적용

1. 아이템 선정: 초보 캠퍼의 선택 불안 해소에 집중하며 실시간 재고·최저가 보장은 제외합니다.
2. 프로젝트 정의: 검색 완료율, 비교 사용률, 상세→예약 CTA율을 향후 측정 지표로 둡니다.
3. 리서치: 모든 시장 수치는 기관·문서·연도·표본·URL로 역추적할 수 있을 때만 사용합니다.
4. 문제/솔루션: 정보 파편화→동일 필드, 조건 이해 부족→도움말, 기억 부담→3곳 비교, 재고 오해→명시적 고지로 연결합니다.
5. 인사이트: 사용자 조사 전 내용은 인사이트가 아니라 가설로 표시합니다.
6. 레퍼런스: 화면을 복제하지 않고 조건 유지·정보 위계·오류 복구 원리를 추출합니다.
7. 디자인 시스템: Forest Green 행동, Amber 주의, Surface 단계, 4/8 간격, 상태별 컴포넌트를 사용합니다.
8. PRD/IA: 정상·로딩·빈 결과·오류·비로그인·결제 실패 상태를 모두 정의합니다.
9. 세계관/카피: 따뜻하지만 과장하지 않는 ‘조용한 캠핑 가이드’를 유지합니다.
10. Vibe Coding: 시맨틱 HTML, 토큰, 입력 이스케이프, Secret 분리, 테스트 가능성을 요구합니다.
11. 정책: 데이터 출처, 예약·환불, 개인정보, 후기, AI 상담 한계를 사용 지점에 연결합니다.
12. QA: 360~1920px, 키보드, 200% 확대, 오류 복구, RLS/CORS/결제 검증을 점검합니다.
13. 고도화: 숲 이미지는 브랜드 구간에 제한하고 정보 구간은 가독성을 우선합니다.
14. 구현: 기반→탐색→비교/신뢰→전환→지원→자동 검수 순으로 진행합니다.

## 구현 완료 조건

- 검색 조건이 결과·상세·뒤로 가기에서 보존됩니다.
- 빈 결과와 API 오류에서 다음 행동을 제공합니다.
- 비교함 0~3개와 최대 초과 상태가 명확합니다.
- 공공데이터의 비실시간성과 갱신 한계를 숨기지 않습니다.
- 키보드만으로 핵심 과업을 수행할 수 있습니다.
- 측정한 결과와 향후 목표를 명확히 구분합니다.
