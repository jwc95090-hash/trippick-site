# TRIPPICK 고객 커뮤니티와 호스트 데모 경계

## 현재 원칙

고객 사이트의 인증·리뷰·상담만 Supabase에 연결합니다. 공개 주소로 열리는 `trippick-host/`는 실제 운영 콘솔이 아니라 예시 데이터만 담은 정적 포트폴리오 데모입니다. 두 화면은 같은 디자인 언어를 사용하지만 데이터 권한과 실행 환경은 분리합니다.

```text
고객 사이트
  ├─ 로그인 → Supabase Auth
  ├─ 리뷰 → public.reviews + RLS
  └─ 상담 → public.board_posts + RLS

공개 호스트센터
  └─ HTML 예시 데이터 + 화면 시연용 JavaScript
     (Supabase, 실제 회원, 실제 예약 데이터 미연결)
```

## 고객 리뷰

- 작성은 로그인한 사용자만 가능하고 `user_id`는 현재 로그인 사용자로 고정합니다.
- 공개 목록은 `status = 'visible'`인 리뷰만 조회합니다.
- 작성자는 본인의 리뷰를 조회·수정·삭제할 수 있습니다.
- 상세페이지, 커뮤니티, 마이페이지가 모두 `js/supabase-app.js`의 같은 데이터 흐름을 사용합니다.

## 고객 상담

- 상담 작성은 로그인한 사용자만 가능합니다.
- 원본 행은 작성자 본인만 직접 조회할 수 있습니다.
- 공개 목록용 `list_board_posts()` 함수는 비밀글의 본문과 답변을 항상 `null`로 바꿔 반환합니다.
- 브라우저 숫자 비밀번호나 localStorage에 민감한 본문을 저장하지 않습니다.

## 호스트센터

- 모든 회원·예약·상담·매출·리뷰는 예시입니다.
- 저장, 상태 변경, 답변 입력은 포트폴리오 인터랙션 시연용입니다.
- 관리 화면에는 `noindex,nofollow,noarchive`를 적용했습니다.
- 실제 운영 관리자 앱은 별도 비공개 주소, 관리자 인증, 역할 기반 권한, 감사 로그를 갖춰야 합니다.

## 관련 파일

- `js/supabase-app.js`: 고객 인증·리뷰·상담
- `supabase/migrations/20260823000000_secure_customer_data.sql`: 테이블, 인덱스, RLS, 공개 목록 함수
- `trippick-host/admin.js`: 정적 데모 인터랙션
- `trippick-host/README.md`: 공개 데모 범위

## 운영 전 검증

마이그레이션을 실제 프로젝트에 적용하기 전에 현재 스키마를 백업하고 차이를 검토합니다. 적용 후 `anon`, 사용자 A, 사용자 B 역할로 리뷰와 상담 조회·작성·수정·삭제를 각각 확인하고, 비밀글 본문이 공개 함수에서 절대 반환되지 않는지 테스트해야 합니다.
