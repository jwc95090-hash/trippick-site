01

Problem
Definition

흩어진 정보와 서로 다른 기준 때문에 초보 캠퍼는 자신에게 맞는 장소를 비교하고 예약 전 확인까지 이어가기 어렵습니다.

가설

정보 파편화

지도, 블로그, 예약처를 반복해서 오갑니다.

가설

조건 이해 부족

숙박 유형과 필요한 시설을 판단하기 어렵습니다.

가설

비교 기억 부담

여러 탭의 정보를 사용자가 직접 기억해야 합니다.

확인된 한계

재고 오해

공공데이터는 실시간 재고와 최종 요금을 보장하지 않습니다.

02

Insight &
Direction

결과의 양보다 내 조건이 반영됐다는 확신, 화려한 추천보다 동일한 기준과 데이터의 한계를 명확히 보여주는 경험을 설계했습니다.

Customer Principle

조건 요약 → 동일 필드 → 최대 3곳 비교 → 예약 전 재확인

Host Principle

전체 통계보다 오늘 처리할 예약·상담·후기·정산 업무를 먼저 표시

03

User Flow

대표 과업: 반려견과 성인 2명이 이용할 수 있고 샤워실과 전기가 있는 캠핑장 3곳을 비교하고 예약 전 확인사항을 찾습니다.

07

Validation

측정하지 않은 성공률을 만들지 않습니다. 실제 테스트에서는 과업, 관찰, 심각도, 수정, 재시험 결과를 같은 기준으로 기록합니다.

Functional

검색 조건 보존, 0건, API 오류, 비교 최대 초과, 결제 실패

Accessibility

키보드, 포커스, 200% 확대, 320px 재배치, 모션 감소

Security

입력 이스케이프, RLS, CORS, 권한, 서버 금액 검증

Responsive

360 · 768 · 1024 · 1440 · 1920px
